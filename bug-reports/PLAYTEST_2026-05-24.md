**Severity:** HIGH | **Category:** UX | **Reproduced by:** Elmo, Ernie | **Disputed by:** Grover

**Description:**

- Grover may have used a different click method (console `.click()` vs automated click)
- Timing: shop may need time to fully animate in before clicks register
- Retry logic in Grover's test masked the issue

**Fix priority:** P0 — breaks core shop flow

## 🔍 Root Cause Analysis

### P0 / P2 — CONTINUE Button

**Likely cause:** The button's click handler has a debounce guard that briefly sets `disabled=true` on rapid consecutive clicks. In automated testing, clicks may fire before the button is re-enabled.

**Code paths to check:**
- `_shopContinueBusy` flag in the button's onclick
- Whether `openShop()` properly resets this flag on subsequent opens
- Whether `browser_click` is triggering two events (mousedown + mouseup) where one is dropped

**Open question:** Why did Grover pass? Need to check Grover's methodology — if Grover used `browser_console` `.click()` it would succeed. Investigate difference.

### P1 / P3 — Leaderboard Leak

**Likely cause:** `completeFloor()` calls `showLeaderboard()` but never calls `hideLeaderboard()` or equivalent cleanup before transitioning to the next floor. Check `startNextFloor()` and `floorComplete()` code paths.
